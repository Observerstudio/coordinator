From the client's message to master.

One person owns every request. You hear the client, decide what only you can, and push to master. In between, a coordinator briefs lanes and gates every PR. Below: how it works, then one request played through.

What our workflow is

Three layers, one gate. Everything still runs on git, gh and GitHub PRs. No new tool for humans.

A humanSets direction and keeps the calls that are theirs: client decisions, production data, the push to master.
A coordinatorOne agent per work track does the judgment: diagnoses, writes a one-page brief per task, cold-reviews every PR against a ten-item rubric, runs the shared integration slot, merges. It never writes feature code.
LanesCheap agents in their own worktrees do the typing. One brief in, one PR out, one sentinel line saying done or blocked.
MemoryDated notes in the repo, a bites file per hard lesson, an incident registry every agent reads before touching money code.

Why it is efficient

Attention goes where it is scarce. The expensive model reads and decides. The cheap model types. One brief per task means nothing is re-explained.

Parallel by default, safe by construction. A worktree per lane, one integration slot, CI that cannot skip to green. The gate catches what CI cannot, and each catch becomes a rule the next agent reads.

Three principles

The replay above is built on them. So is every real day.

Clarity
One brief in, one sentinel line out, one gate comment per PR. Nothing is explained twice. Above: the Brief station, the LANE-DONE line, the 10/10 chip.
Simplicity
The workflow is markdown in the repo plus git and gh. A skill file, a brief template, a review rubric. No new tool for humans.
Adoption
Three humans merge under the same gate today. The skill loads itself every session. A lane needs nothing but a worktree and a brief.

Six things that do not bend

  • Build the spec, nothing around it.Do not shrink the product; enhance it.
  • Never force-push.Amended history goes on a new branch with a new PR.
  • Lanes never delegate.Work happens where it can be seen.
  • Idle is not finished.Only the sentinel line is. A quiet pane gets a nudge, not a merge.
  • Coordinators write no feature code.Briefs, reviews and notes are their files.
  • Findings that live only in chat did not happen.A dated note, merged by PR.
